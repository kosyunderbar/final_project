ESP32가 무엇이고, 우리 프로젝트에서 무슨 일을 하나

읽고 나면: ESP32 다섯 대가 각각 무엇을 맡는지 그림 한 장으로 설명할 수 있다.

ESP32는 Wi-Fi가 달린 손가락만 한 컴퓨터입니다. 운영체제 없이 우리가 올린 프로그램 하나만 켜지자마자 돌립니다. 핀으로 전기 신호를 읽고 쓰고, Wi-Fi로 메시지를 주고받습니다.

우리 라인에서는 공정 P1~P4마다 ESP32 한 대가 공정 하나를 혼자 맡습니다. RFID 리더기(RC522)로 차체의 키태그를 읽고, 설비(서보·모터·상태등·부저·버튼)를 움직이고, Wi-Fi로 관제 Pi5와 MQTT 메시지를 주고받는 일을 모두 이 한 대가 합니다. 차체에 붙는 스마트태그도 ESP32입니다.

펌웨어 안은 두 부분으로 나눕니다. 설비 쪽(리더기·버튼 읽기, 작업 순서, 모터·등·부저)과 통신 쪽(Wi-Fi·MQTT)입니다. 둘을 FreeRTOS 태스크 두 개로 나눠 큐로만 주고받게 짜는 것이 계획입니다(RTOS판, 사용자 확정·팀 확인 전, 9장). P2에서 먼저 검증하고, 12-01까지 안정되지 않으면 loop 하나에서 차례로 부르는 loop판(modem.ino 바탕)으로 갑니다.

공정 ESP32 한 대가 공정 하나의 리더기·설비·통신을 모두 맡습니다. 작업 순서와 이상 판단은 공정 ESP32가, 기록과 화면은 관제 Pi5가 맡습니다.
무엇수량하는 일
공정 ESP324P1~P4 공정마다 한 대. 리더기(RC522)로 차체 키태그를 읽고, 서보·모터·상태등·부저·버튼을 다루고, Wi-Fi(MQTT)로 관제 Pi5와 주고받습니다. 네 대가 같은 뼈대이고 공정 이름과 '작업 동작'만 다릅니다
스마트태그1차체에 부착. 관제가 보내는 이력 사본을 받아 저장하고, 불빛과 버튼이 있습니다

이 교본에서 다루지 않는 것: 블루투스, 절전, 무선 업데이트, ESP-IDF, FreeRTOS의 깊은 내용(태스크 두 개와 큐만 9장에서 다룹니다). 4주 안에 쓸 일이 없습니다. 납땜도 여기서는 하지 않고 점퍼선만 씁니다.

개발 환경과 첫 업로드 (Windows)

  3. Library Manager에서 PubSubClient(Nick O'Leary), ArduinoJson(Benoit Blanchon, 7.x), MFRC522(GithubCommunity, 1.4.x — 실습 5)를 설치합니다.
  4. Tools → Board → esp32 → NodeMCU-32S. 없으면 ESP32 Dev Module.

explorer C:\esp32
업로드가 안 될 때, 이 순서로. ① 케이블을 바꿉니다(충전 전용 케이블이면 포트가 아예 안 뜹니다. 가장 흔한 원인). ② Serial Monitor와 그 포트를 쓰는 다른 프로그램을 닫습니다(Could not open port 'COM5'). ③ BOOT 버튼을 누른 채 업로드를 시작하고 "Writing"이 보이면 뗍니다. ④ 핀 0·2·12·15에 꽂은 선을 뺍니다. ⑤ Upload Speed를 115200으로 낮춥니다.

핀 읽고 쓰기, 그리고 멈추지 않는 loop

읽고 나면: delay 없이 불빛을 깜빡이면서 버튼의 짧게·길게 누름을 구분할 수 있다.

핀(GPIO)

전압으로 읽고 쓰는 참·거짓 변수입니다. 3.3V가 참, 0V가 거짓.

풀업

아무도 안 건드릴 때의 기본값입니다. 없으면 초기화 안 한 변수처럼 값이 떠돕니다. 그래서 버튼은 눌렀을 때 LOW입니다.

setup과 loop

setup은 켜질 때 한 번, loop는 끝없이 반복됩니다. 이벤트 루프와 같습니다.

delay를 쓰면

프로그램 전체가 잠듭니다. 그동안 버튼도, 리더기도, 시리얼로 오는 글자도, Wi-Fi도 놓칩니다.

스마트태그의 배정입니다(불빛 IO25, 버튼 IO33). 부품이 없으면 보드의 내장 LED(IO2)와 BOOT 버튼(IO0)으로 연습할 수 있습니다.
// delay 대신: "지난번 이후 얼마나 지났나"만 본다
static uint32_t last = 0;
if (millis() - last >= 500) {        // 0.5초마다
  last = millis();
  digitalWrite(25, !digitalRead(25)); // 불빛 뒤집기
}

// 버튼: 눌림 = LOW. 30ms 동안 같은 값이면 진짜로 본다(떨림 거르기)
pinMode(33, INPUT_PULLUP);
bool pressed = digitalRead(33) == LOW;

우리 라인에서 이게 왜 중요한가: 이상이 났을 때 버튼을 짧게 누르면 '봤다', 2초 누르면 '해제'입니다. 누르는 시간을 재려면 프로그램이 멈추지 않아야 합니다.

시리얼과 우리의 한 줄 규격

읽고 나면: 설비 쪽과 통신 쪽이 주고받는 $…*XX 줄을 읽고, 검사값을 확인하고, USB 시리얼로 직접 쳐서 공정을 흉내 낼 수 있다.

UART는 선 두 가닥으로 글자를 차례로 보내는 통신입니다. ESP32에는 여러 개가 있고, 그중 USB에 이어진 것이 Serial입니다.

이름핀어디로쓰임
Serial1, 3USB를 거쳐 PC업로드와 로그. 시험할 때는 Serial Monitor에 줄을 쳐서 설비 쪽을 흉내 냅니다
다른 UART(Serial2)를 쓸 일이 생기면 핀 번호를 꼭 직접 적으세요. 새 버전(3.x)에서 Serial2의 기본 핀이 바뀌었습니다. 인터넷 예제처럼 Serial2.begin(115200)만 쓰면 16·17이 아닌 다른 핀으로 나갑니다. 
Serial2.begin(115200, SERIAL_8N1, 16, 17);   // RX=16, TX=17
RTOS판에서는 같은 내용을 칩 안의 큐로 넘깁니다(큐에 담는 모양은 회의에서 정함, 권장안은 이 줄 형식 그대로). 시험할 때는 Serial Monitor에 줄을 쳐서 설비 쪽을 흉내 냅니다(modem.ino의 TEST_MODE 1, 실습 7). 칩 안에서 큐로 넘길 때는 검사값을 생략할 수 있지만, 사람이 칠 때는 오타를 잡아 줍니다.

한 줄의 모양

$R{"n":42,"k":"DONE"}*7B
$ 와 *시작과 끝 표시
종류 한 글자설비 쪽 → 통신 쪽: T 태그 읽음, R 신고, H 살아 있음. 통신 쪽 → 설비 쪽: C 답, S 지금 상태, L 연결 상태, X 시험 입력
내용설비 쪽이 보내는 것은 JSON 그대로(통신 쪽이 그대로 발행). 설비 쪽이 받는 것은 이름=값을 쉼표로 이은 것(설비 쪽이 JSON을 풀지 않아도 되게)
검사값 2자리$ 와 * 사이의 모든 글자(종류 글자 포함)를 XOR한 값을 16진수 두 자리로. 글자가 깨졌거나 잘못 쳤는지 알아냅니다

검사값 계산기

문서나 메신저에서 복사하면 따옴표가 둥근 모양(“ ”)으로 바뀌어 검사값이 틀려집니다. 그럴 때는 직접 치세요.

Wi-Fi와 MQTT

읽고 나면: 브로커에 붙어 메시지를 보내고 받고, '보관'과 '유언'을 쓸 수 있다.

브로커와 토픽

우체국과 주소입니다. 보내는 쪽은 주소(토픽)에 붙이기만 하고, 누가 받는지 모릅니다. 받는 쪽은 주소를 구독합니다.

보관 (retained)

게시판에 붙여 둔 마지막 쪽지입니다. 늦게 온 구독자도 붙자마자 봅니다. 우리의 '지금 상태'와 '연결 상태'가 이것입니다.

유언 (LWT)

브로커에 미리 맡겨 둔 메시지입니다. 내가 말없이 사라지면 브로커가 대신 붙입니다. "이 공정 끊김"을 이것으로 알립니다.

Wi-Fi는 2.4GHz만

ESP32는 5GHz에 붙지 못합니다. 학교 인증 Wi-Fi도 안 됩니다. 전용 공유기나 휴대폰 핫스팟(2.4GHz)을 씁니다.

공정 이름만 바꾸면 네 공정이 모두 같습니다. 스마트태그는 factory/tag/{이름}/cmd · report · link를 씁니다.
// 연결 → 구독 → loop()를 계속 부른다. 다시 연결되면 구독도 다시 한다
mqtt.setServer(MQTT_HOST, 1883);
mqtt.setCallback(onMqtt);
mqtt.setBufferSize(512);                 // 기본 256바이트는 모자란다
mqtt.setKeepAlive(4);                    // 말없이 죽으면 약 6초 뒤 유언이 나간다

// 유언: 내가 죽으면 link=0(보관). 붙자마자 내가 link=1(보관)
if (mqtt.connect("modem-P2", "factory/station/P2/link", 0, true, "0")) {
  mqtt.publish("factory/station/P2/link", "1", true);
  mqtt.subscribe("factory/station/P2/cmd");
  mqtt.subscribe("factory/station/P2/state");
}
mqtt.loop();                             // 이게 없으면 받은 메시지가 처리되지 않는다

import argparse
import json
import sys
import time

try:

except ImportError:

def make_client(name):
    try:   # paho-mqtt 2.x
        return mqtt.Client(mqtt.CallbackAPIVersion.VERSION2, client_id=name)
    except AttributeError:   # 1.x
        return mqtt.Client(client_id=name)


def connect(c, host, port):
    try:
        c.connect(host, port, keepalive=30)
    except OSError as e:
        sys.exit(f"브로커({host}:{port})에 붙지 못했습니다: {e}\n"
                 "mosquitto가 켜져 있는지, IP가 맞는지, 방화벽에서 1883이 열려 있는지 보세요.")


def now():
    return time.strftime("%H:%M:%S")


def cmd_watch(a):
    c = make_client("pc-watch")
    c.on_connect = lambda cl, *_: (cl.subscribe("factory/#"), print(f"{now()} 연결됨 — factory/# 보는 중 (끝내려면 Ctrl+C)"))
    c.on_message = lambda cl, u, m: print(f"{now()} {m.topic}{' [보관]' if m.retain else ''}  {m.payload.decode(errors='replace')}")
    connect(c, a.host, a.port)
    c.loop_forever()


def publish_once(a, topic, payload, retain=False):
    c = make_client("pc-send")
    connect(c, a.host, a.port)
    c.loop_start()
    info = c.publish(topic, payload, qos=1, retain=retain)
    info.wait_for_publish(5)
    c.loop_stop()
    c.disconnect()
    print(f"{now()} 보냄 {topic}{' [보관]' if retain else ''}  {payload}")


def to_value(v):
    try:
        return int(v)
    except ValueError:
        return v


def cmd_send(a):
    obj = {}
    for kv in a.pairs:
        if "=" not in kv:
            sys.exit(f"이름=값 모양이 아닙니다: {kv}  (예: re=42 ok=1)")
        k, v = kv.split("=", 1)
        obj[k] = to_value(v)
    publish_once(a, f"factory/station/{a.station}/cmd", json.dumps(obj, separators=(",", ":")))


def cmd_state(a):
    payload = json.dumps({"st": a.st, "job": a.job, "lamp": a.lamp, "fault": 0}, separators=(",", ":"))
    publish_once(a, f"factory/station/{a.station}/state", payload, retain=True)


def cmd_reply(a):
    c = make_client("pc-reply")

    def on_connect(cl, *_):
        cl.subscribe("factory/station/+/report")
        cl.subscribe("factory/station/+/tag")
        print(f"{now()} 연결됨 — 공정의 report·tag에 자동으로 답합니다 (끝내려면 Ctrl+C)")

    def on_message(cl, u, m):
        station = m.topic.split("/")[2]
        text = m.payload.decode(errors="replace")
        try:
            n = json.loads(text).get("n")
        except ValueError:
            print(f"{now()} {m.topic}  JSON 아님, 답 안 함: {text}")
            return
        print(f"{now()} 받음 {m.topic}  {text}")
        if n is None:
            return
        ans = json.dumps({"re": n, "ok": 1}, separators=(",", ":"))
        cl.publish(f"factory/station/{station}/cmd", ans, qos=1)
        print(f"{now()} 답함 factory/station/{station}/cmd  {ans}")

    c.on_connect, c.on_message = on_connect, on_message
    connect(c, a.host, a.port)
    c.loop_forever()


def main():
    p = argparse.ArgumentParser(description="ESP32 실습용 MQTT 도구")
    p.add_argument("--host", default="localhost")
    p.add_argument("--port", type=int, default=1883)

    s = sub.add_parser("state"); s.add_argument("station"); s.add_argument("st"); s.add_argument("job", type=int)
    s.add_argument("--lamp", default="Yb")
    sub.add_parser("reply")
    a = p.parse_args()
    try:
        {"watch": cmd_watch, "send": cmd_send, "state": cmd_state, "reply": cmd_reply}[a.cmd](a)
    except KeyboardInterrupt:
        print("\n끝")


if __name__ == "__main__":

끊김과 복구, 그리고 꺼져도 남는 저장

읽고 나면: 끊겨도 스스로 다시 붙게 만들고, 전원이 꺼져도 값을 남길 수 있다.

영상으로 찍을 장면이 바로 이것입니다. 밀린 신고를 쥐고 다시 보내는 일은 설비 쪽이 하고, 통신 쪽은 연결을 되살리는 일만 합니다. 새 작업은 다시 붙을 때까지 시작하지 않습니다.

왜 바로 0이 안 되나. 전원이 뽑히면 "끊는다"는 말을 못 합니다. 브로커는 약속한 시간(keepalive)의 1.5배 동안 소식이 없어야 유언을 붙입니다. 4초로 두면 약 6초입니다.

다시 붙는 코드는 loop 안에 있어야 합니다. setup에서 한 번만 연결하면 끊긴 뒤 영영 돌아오지 않습니다. 기다릴 때도 while로 붙잡지 말고 millis()로 3초마다 한 번씩만 시도합니다.

#include <Preferences.h>
Preferences nv;
nv.begin("tag", false);                  // 이름표 "tag" (15자 이하)
uint32_t seq = nv.getUInt("seq", 0);     // 없으면 0
nv.putUInt("seq", 1042);                 // 전원이 꺼져도 남는다

저장장치(플래시)는 작은 SSD입니다. 꺼져도 남지만 쓰는 횟수에 한계가 있습니다. 값이 바뀔 때만 쓰고, loop에서 매번 쓰지 않습니다. 스마트태그가 이력 사본을 이렇게 저장합니다.

재부팅을 되풀이하면서 "Brownout"이 찍힌다면 전기가 모자란 것입니다. Wi-Fi를 켜는 순간 전류가 크게 튑니다. 짧은 케이블을 PC에 직접 꽂고, 서보 같은 부품은 다른 전원에서 먹입니다.

// ───── 체크섬 / 설비 쪽으로 한 줄 보내기 ─────
uint8_t xorOf(const char *p, size_t n) { uint8_t c = 0; while (n--) c ^= (uint8_t)*p++; return c; }

void sendToBoard(const char *body) {          // body = 종류 글자 + 내용, 예: "C,re=42,ok=1"
  BOARD.printf("$%s*%02X\n", body, xorOf(body, strlen(body)));
  DBG("# ->board $%s\n", body);
}

// ───── 설비 쪽 → MQTT ─────
void handleLine(char *line, size_t len) {     // line = "$...*HH" (개행 제거됨)
  if (len < 5 || line[0] != '$' || line[len - 3] != '*') { DBG("# 형식 오류: %s\n", line); return; }
  char *end;
  uint8_t want = (uint8_t)strtoul(line + len - 2, &end, 16);
  if (end != line + len || xorOf(line + 1, len - 4) != want) { DBG("# 체크섬 오류: %s\n", line); return; }

  char type = line[1];
  const uint8_t *payload = (const uint8_t *)line + 2;   // 종류 글자 다음부터 '*' 앞까지
  size_t plen = len - 5;
  const char *topic = type == 'T' ? BASE "tag" : type == 'R' ? BASE "report" : type == 'H' ? BASE "alive" : nullptr;
  if (!topic) { DBG(TEST_MODE == 2 ? "# 루프백 OK: %s\n" : "# 모르는 종류: %s\n", line); return; }
  if (!mqtt.connected()) { DBG("# 링크 없음, 버림 (보드가 재전송)\n"); return; }
  bool ok = mqtt.publish(topic, payload, plen, false);  // JSON을 그대로, QoS 0
  DBG("# ->mqtt %s %s\n", topic, ok ? "ok" : "실패(버퍼 초과?)");
}

void pollBoard() {                            // 한 글자씩 모아서 '\n'에서 한 줄 완성. 절대 기다리지 않는다
  static char buf[LINE_CAP + 1];
  static size_t n = 0;
  static bool over = false;
  while (BOARD.available()) {
    char c = (char)BOARD.read();
    if (c == '\r') continue;
    if (c == '\n') {
      if (over) DBG("# 줄이 너무 김, 버림\n");
      else if (n) { buf[n] = 0; handleLine(buf, n); }
      n = 0; over = false;
    } else if (n < LINE_CAP) buf[n++] = c;
    else over = true;                         // 길이 초과: 다음 '\n'까지 통째로 버린다
  }
}

// ───── MQTT → 설비 쪽: JSON {"re":42,"ok":1} → "$C,re=42,ok=1*67" ─────
void onMqtt(char *topic, byte *payload, unsigned int len) {
  if (strncmp(topic, BASE, strlen(BASE)) != 0) return;
  const char *leaf = topic + strlen(BASE);
  char type = !strcmp(leaf, "cmd") ? 'C' : !strcmp(leaf, "state") ? 'S' : !strcmp(leaf, "test") ? 'X' : 0;
  if (!type) return;

  JsonDocument doc;                           // payload는 0으로 끝나지 않는다 → 길이를 꼭 넘긴다
  DeserializationError err = deserializeJson(doc, (const char *)payload, len);
  JsonObject obj = doc.as<JsonObject>();
  if (err || obj.isNull()) { DBG("# JSON 오류(%s): %s\n", leaf, err.c_str()); return; }

  char body[LINE_CAP - 3];
  size_t n = 0;
  body[n++] = type; body[n] = 0;
  for (JsonPair kv : obj) {                   // 보낸 순서 그대로 나온다
    const char *k = kv.key().c_str();
    if (type == 'S' && !strcmp(k, "body")) continue;      // state의 body는 설비 쪽에 안 보낸다
    char val[48];
    JsonVariant v = kv.value();
    if (v.is<JsonObject>() || v.is<JsonArray>()) { DBG("# 중첩 값 거부: %s\n", k); return; }
    size_t vl = v.is<const char *>() ? strlcpy(val, v.as<const char *>(), sizeof val)
                                     : serializeJson(v, val, sizeof val);   // 숫자는 글자로
    if (vl >= sizeof val || strpbrk(k, ",=*$\r\n") || strpbrk(val, ",=*$\r\n")) { DBG("# 값 거부: %s\n", k); return; }
    int w = snprintf(body + n, sizeof body - n, ",%s=%s", k, val);
    if (w < 0 || (size_t)w >= sizeof body - n) { DBG("# 줄 길이 초과\n"); return; }
    n += w;
  }
  sendToBoard(body);
}

// ───── Wi-Fi / MQTT 유지 (loop에서 계속 호출, 기다리지 않음) ─────
void serviceWifi() {
  static uint32_t lastTry = 0;
  static bool was = false;
  bool ok = WiFi.status() == WL_CONNECTED;
  if (ok && !was) DBG("# WiFi 연결 %s\n", WiFi.localIP().toString().c_str());
  if (!ok && was) DBG("# WiFi 끊김\n");
  was = ok;
  if (!ok && millis() - lastTry >= 15000) {   // 15초마다 처음부터 다시 시도
    lastTry = millis();
    WiFi.disconnect();
    WiFi.begin(WIFI_SSID, WIFI_PASS);
  }
}

void serviceMqtt() {
  static bool wasUp = false;
  static uint32_t lastTry = 0, lastLink = 0;
  bool up = mqtt.connected();
  if (up) {

  } else if (WiFi.status() == WL_CONNECTED && millis() - lastTry >= 3000) {
    lastTry = millis();

    uint32_t t0 = millis();

#if MEASURE
    DBG("# [측정] connect %s %lums\n", ok ? "성공" : "실패", (unsigned long)(millis() - t0));
#endif
    if (ok) {
      mqtt.publish(BASE "link", "1", true);   // retained
      mqtt.subscribe(BASE "cmd");
      mqtt.subscribe(BASE "state");           // retained라 구독 즉시 현재 상태가 온다 → $S가 설비 쪽으로 간다
      mqtt.subscribe(BASE "test");
      up = true;
      DBG("# MQTT 연결\n");
    } else DBG("# MQTT 실패 rc=%d\n", mqtt.state());
  }
  if (up != wasUp || (LINK_REPEAT_MS && millis() - lastLink >= LINK_REPEAT_MS)) {

    sendToBoard(up ? "L,up=1" : "L,up=0");
  }
}

  nv.begin("tag", false);                     // 이름공간 "tag", 읽기/쓰기

void logAdd(const Rec &r) {
  char key[8]; snprintf(key, sizeof key, "r%u", (unsigned)head);

void onMqtt(char *topic, byte *payload, unsigned int len) {
  if (strcmp(topic, BASE "cmd") != 0) return;
  JsonDocument doc;
  if (deserializeJson(doc, (const char *)payload, len)) { setState(ST_ERROR); return; }
  const char *what = doc["do"] | "";          // 키가 없으면 "" (기본값)
  uint16_t id = doc["id"] | 0;
  if (strcmp(what, "WRITE") == 0) {
    Rec r = {};
    r.seq = doc["seq"] | 0u; r.id = id;
    strlcpy(r.body, doc["body"] | "", sizeof r.body);
    strlcpy(r.p, doc["p"] | "", sizeof r.p);
    strlcpy(r.r, doc["r"] | "", sizeof r.r);
    if (count == 0 || r.seq != lastSeq) logAdd(r);   // 같은 seq 재전송이면 저장은 건너뛰고 답만 다시
    lastId = id;
    answer(id);                               // payload는 이미 다 복사했으므로 여기서 publish해도 안전
    setState(ST_WROTE);
  }
}

void pollButton() {
  static bool stable = HIGH, last = HIGH, longDone = false;
  static uint32_t tEdge = 0, tDown = 0;
  bool now = digitalRead(PIN_BTN);
  if (now != last) { last = now; tEdge = millis(); }
  if (now != stable && millis() - tEdge >= 30) {
    stable = now;
    if (stable == LOW) { tDown = millis(); longDone = false; }
    else if (!longDone) onShort();            // 길게 누르기가 이미 처리됐으면 뗄 때는 무시
  }
  if (stable == LOW && !longDone && millis() - tDown >= 1500) { longDone = true; onLong(); }
}

void serviceNet() {
  static uint32_t lastWifi = 0, lastMqtt = 0;
  if (WiFi.status() != WL_CONNECTED) {
    if (millis() - lastWifi >= 15000) { lastWifi = millis(); WiFi.disconnect(); WiFi.begin(WIFI_SSID, WIFI_PASS); }

      mqtt.publish(BASE "link", "1", true);
      mqtt.subscribe(BASE "cmd");

/* body = '$'와 '*' 사이 전부 (종류 글자 포함) */
uint8_t frame_xor(const char *body, size_t len) {
    uint8_t cs = 0;
    while (len--) cs ^= (uint8_t)*body++;
    return cs;
}
/* out에 "$body*HH\n" 작성. 반환: 길이, 공간 부족이면 0 */
int frame_build(char *out, size_t cap, const char *body) {
    int n = snprintf(out, cap, "$%s*%02X\n", body, frame_xor(body, strlen(body)));
    return (n > 0 && (size_t)n < cap) ? n : 0;
}
/* line = "$....*HH" (개행 제거된 상태). 맞으면 1, body 시작/길이를 돌려줌 */
int frame_check(const char *line, size_t len, const char **body, size_t *blen) {
    if (len < 5 || line[0] != '$' || line[len - 3] != '*') return 0;
    char hex[3] = { line[len - 2], line[len - 1], 0 };
    char *end;
    unsigned long want = strtoul(hex, &end, 16);
    if (end != hex + 2) return 0;
    if (frame_xor(line + 1, len - 4) != (uint8_t)want) return 0;
    *body = line + 1; *blen = len - 4;
    return 1;
}

공정 ESP32 펌웨어는 처음부터 이 구조로 짭니다(사용자 확정, 팀 확인 전). P2에서 먼저 검증하고, 12-01까지 안정되지 않으면 loop판(modem.ino 바탕)으로 갑니다. 근거와 일정은 next_meeting/RTOS_도입_제안서.pdf에 있습니다.

왜 나누나. loop 하나로 돌면, 통신 쪽이 서버 접속(mqtt.connect())을 기다리는 동안 버튼·리더기·작업도 같이 멈춥니다. 얼마나 막히는지는 11-24에 loop판으로 잽니다(관제 Pi5를 끈 경우 / 공유기를 끈 경우 각 20번).

태스크는 칩 안에서 동시에 도는 작은 프로그램이고, 큐는 태스크끼리 메시지를 넣고 꺼내는 통입니다. ESP32는 코어가 두 개라 설비 태스크는 코어 1, 통신 태스크는 코어 0에 둡니다. 통신 태스크가 접속을 기다리는 동안에도 설비 태스크는 10ms 박자를 지킵니다.

이렇게 말합니다: '고장 분리'가 아니라 '작업 분리'입니다. 칩이 통째로 리셋되면 둘 다 멈춥니다. 잘 짠 loop로도 같은 일을 할 수 있지만, 태스크는 그것을 구조로 보장하는 방법입니다.

P1~P4 모두 같은 구조이고, 공정마다 다른 것은 설비 태스크의 '작업 동작'뿐입니다. 두 태스크는 서로 직접 부르지 않고 큐로만 주고받습니다.

설비 태스크는 내장 LED(IO2)를 0.2초마다, 통신 태스크는 IO25 LED를 1초마다 뒤집습니다. BOOT 버튼(IO0)을 누르면 설비 태스크가 신고 줄을 신고 큐에 넣고, 통신 태스크가 꺼내 출력한 뒤 답($C)을 명령 큐로 돌려줍니다. 답을 받으면 내장 LED가 0.5초 켜져 있습니다. Wi-Fi는 아직 쓰지 않습니다. IO25 LED가 없으면 시리얼 출력으로 확인합니다.

// rtos_step1.ino — 실습 10 1단계: FreeRTOS 태스크 두 개 + 큐 두 개 (컴파일 확인 전)
// 대상: Arduino-ESP32 3.3.x. 부품: 내장 LED(IO2), BOOT 버튼(IO0). 선택: IO25 LED + 220Ω
// Wi-Fi는 아직 쓰지 않는다. secrets.h도 필요 없다.
#include <Arduino.h>

#define PIN_LED_CTRL 2     // 설비 태스크만 만진다 (내장 LED)
#define PIN_BTN      0     // 설비 태스크만 만진다 (BOOT 버튼, 눌림 = LOW)
#define PIN_LED_COMM 25    // 통신 태스크만 만진다 (없으면 시리얼 출력으로 확인)

struct Msg { char line[160]; };   // 큐 한 칸 = 한 줄 (교본 5장의 줄 형식, 칩 안이라 검사값 생략)
QueueHandle_t toComm, toCtrl;     // 설비 → 통신 (신고 큐) / 통신 → 설비 (명령 큐)

// ───── 설비 태스크: 코어 1 · 우선순위 3 · 10ms 박자. 절대 기다리지 않는다 ─────
void ctrlTask(void *) {
  pinMode(PIN_LED_CTRL, OUTPUT);
  pinMode(PIN_BTN, INPUT_PULLUP);
  TickType_t t = xTaskGetTickCount();
  uint32_t tick = 0, tEdge = 0, holdUntil = 0, n = 0;
  bool stable = HIGH, last = HIGH;
  for (;;) {
    tick++;                                        // 10ms마다 1씩
    bool now = digitalRead(PIN_BTN);               // 버튼: 30ms(3박자) 같은 값이면 진짜
    if (now != last) { last = now; tEdge = tick; }
    if (now != stable && tick - tEdge >= 3) {
      stable = now;
      if (stable == LOW) {                         // 눌린 순간 한 번
        Msg m;
        n = n % 255 + 1;                           // 신고 번호 1~255
        snprintf(m.line, sizeof m.line, "$R{\"n\":%lu,\"k\":\"BTN\"}", (unsigned long)n);
        xQueueSend(toComm, &m, 0);                 // 기다림 0. 꽉 차면 못 넣는다(1단계는 그냥 둔다)
      }
    }
    Msg in;
    while (xQueueReceive(toCtrl, &in, 0) == pdTRUE) {   // 기다림 0, 있는 만큼만 꺼낸다
      if (in.line[1] == 'C') holdUntil = tick + 50;     // 답이 오면 0.5초 동안 켜 둔다
    }
    bool on = (tick < holdUntil) || ((tick / 20) % 2);  // 평소에는 0.2초마다 뒤집기
    digitalWrite(PIN_LED_CTRL, on);
    vTaskDelayUntil(&t, pdMS_TO_TICKS(10));        // delay() 대신. 10ms 박자를 지킨다
  }
}

// ───── 통신 태스크: 코어 0 · 우선순위 2. Serial도 이 태스크만 쓴다 ─────
void commTask(void *) {
  pinMode(PIN_LED_COMM, OUTPUT);
  bool led = false;
  uint32_t lastBlink = 0;
  for (;;) {
    // 2단계: 여기에 modem.ino의 serviceWifi(); serviceMqtt(); 가 들어간다
    Msg out;
    while (xQueueReceive(toComm, &out, 0) == pdTRUE) {
      Serial.printf("[N] 받음 %s\n", out.line);    // 2단계: 여기서 MQTT로 발행
      int n = 0;
      sscanf(out.line, "$R{\"n\":%d", &n);
      Msg ans;
      snprintf(ans.line, sizeof ans.line, "$C,re=%d,ok=1", n);
      xQueueSend(toCtrl, &ans, 0);                 // 답을 설비 쪽으로 (2단계: cmd 토픽으로 온 답)
    }
    if (millis() - lastBlink >= 1000) {            // 1초마다 뒤집기 (설비 쪽보다 느리게)
      lastBlink = millis();
      led = !led;
      digitalWrite(PIN_LED_COMM, led);
    }
    vTaskDelay(pdMS_TO_TICKS(5));                  // 잠깐 쉬어 다른 태스크(워치독 포함)에 차례를 준다
  }
}

void setup() {
  Serial.begin(115200);
  Serial.println("\n[N] rtos_step1 시작");         // 태스크를 만들기 전이라 섞이지 않는다
  toComm = xQueueCreate(8, sizeof(Msg));           // 8칸 × 160바이트
  toCtrl = xQueueCreate(8, sizeof(Msg));
  xTaskCreatePinnedToCore(ctrlTask, "ctrl", 6144, nullptr, 3, nullptr, 1);   // 스택 6KB, 코어 1
  xTaskCreatePinnedToCore(commTask, "comm", 8192, nullptr, 2, nullptr, 0);   // 스택 8KB, 코어 0
}

void loop() { vTaskDelete(nullptr); }              // loop는 쓸 일이 없어 스스로 지운다

다음 단계

  1. 2단계: 통신 태스크에 modem.ino의 serviceWifi()·serviceMqtt()·onMqtt()를 옮깁니다. Serial.printf 자리에서 MQTT로 발행하고, cmd로 온 답을 명령 큐에 넣습니다. onMqtt()는 mqtt.loop() 안에서 불리므로 통신 태스크 안에서 돕니다.
  2. 3단계: 설비 태스크에 리더기, 작업 순서, 서보를 붙입니다. P2에서 먼저 합니다.

지킬 규칙 세 가지

  1. 함께 쓰는 변수 0개. 주고받는 것은 모두 큐로 합니다. 두 태스크는 동시에 돌기 때문에 같은 변수를 같이 읽고 쓰면 값이 엉킵니다.
  2. 한 장치는 한 태스크만. Wi-Fi·MQTT는 통신 태스크, SPI(리더기)·공정 핀은 설비 태스크가 만집니다. PubSubClient는 여러 태스크가 같이 부르면 안 됩니다.
  3. 설비 태스크는 기다리지 않는다. 큐는 기다림 0으로 넣고 꺼내고, delay() 대신 vTaskDelayUntil로 10ms 박자를 맞춥니다. 큐가 차면 신고는 버리지 않고 설비 태스크의 '다시 보낼 목록'에 남깁니다.
