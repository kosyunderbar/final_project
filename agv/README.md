# AGV 주행 코드

AGV(JETANK)가 매트의 검은 선을 반시계로 돈다. **몸통 정중앙이 검은 선 위로** 가는 것이 목표다(모서리에서도).
"언제 서나 / 언제 출발하나"는 `conditions.py` 한 곳에 있어서, 나중에 그 함수만 MQTT("태그 읽음" / "작업 완료")로 바꾼다.

주행 방식은 **상황별 주행 하나**다(`situ.py`). 이전 방식들(화면 가운데 맞춤, 학습 모델, 정해 둔 호 돌기, 선 기억)은 2026-11-26에 코드에서 지웠다. 왜 버렸는지는 `진행기록_1125.md`, `진행기록_1126.md`에 있다.

## 상황별 주행이 하는 일
카메라는 차체 중심보다 13~25cm 앞 바닥만 본다. 선을 기억하지 않고, 지금 보이는 것으로만 판단한다. 회전은 시간·각도가 아니라 카메라가 끝낸다.

| 상태 | 언제 | 무엇을 하나 |
|---|---|---|
| LINE | 선이 보임 | 선의 옆 오차 e와 방향 ψ로 조향. 조금 틀어지면 달리며 꺾고, 10° 넘게 틀어지면 서서 제자리 회전(ALIGN)으로 먼저 맞춤 |
| APP | 앞쪽 선이 왼쪽으로 휨(3장 연속) | 속도를 줄여 직진 |
| COR | 화면 맨 아랫줄의 선이 왼쪽 7cm에 닿음 | 2cm 더 가서 제자리 좌회전 → 선이 6cm 안으로 들어오면 직진 → 반복. 나가는 곧은 선 위에 오면 방향을 맞추고 LINE으로 |
| LOST | 선을 놓침 | 모서리가 올 구간이면 왼쪽으로, 아니면 마지막으로 선이 있던 쪽으로 돌며 찾음 |

- 갈림길은 구간 규칙으로 고른다(`config.json` branch.rules): 빨강→노랑 = 왼쪽, 노랑 위 X자 = 직진, 노랑 뒤 ~ 주황 = 오른쪽, 초록·보라 = 오른쪽.
- 모서리는 맵 순서상 올 구간(목표가 orange·green·blue·yellow)에서 구간당 한 번만 시작한다.
- 설계와 근거(사진 검증, 계산): `설계안_1126_상황별주행.md`

## 파일
| 파일 | 내용 |
|---|---|
| `main.py` | Runner: 사진 → 색 판정 → 상태 → 선 찾기 → 상황별 주행 → 모터 → 기록 |
| `situ.py` | 상황별 주행: `NearRow`(아랫줄 선 검출기), `Corner`(모서리 판단), `SituDriver`(상태) |
| `line_tracker.py` | `FloorLineTracker`: 검은 선 마스크, 줄 16개를 따라가며 바닥 좌표 점을 구함 |
| `floor.py`, `calib_floor.py` | 화면 px ↔ 바닥 cm. 보정값은 `floor_calib.json` |
| `color_detector.py`, `calib_hsv.py` | 색 구역 판정, 색 값 재기 |
| `fsm.py`, `conditions.py` | 구역 순서·정지·출발 상태 기계, 정지/출발 조건 |
| `drive.py`, `common.py`, `logger.py` | 모터 명령, 설정·카메라, 주행 기록(csv + 사진) |
| `calib_motion.py` | 직진 속도 재기(카메라로, 자 필요 없음) |
| `replay.py` | 저장한 사진을 순서대로 넣어 다시 돌려 보기(매트 없이) |
| `tools/sim_situ.py` | 모서리 모의 시험(로봇과 같은 `situ` 클래스를 씀) |
| `tools/test_fsm.py` | 상태 기계 시험 11개 |
| `tools/build_notebook.py` | `run_agv.ipynb` 생성기 (노트북을 직접 고치지 말고 이 파일을 고친다) |
| `config.json` | 모든 숫자. 주행 관련은 ctrl(`_note_situ`에 설명) |

AGV에서는 `~/final/agv`(= 컨테이너 `/workspace/final/agv`). 이 PC의 파일이 원본이고 `scp`로 올린다.

## 쓰는 법
- 현장: `run_agv.ipynb`. `서기 = 통과만`, `막 떠난 구역`을 고르고 `출발`. `달리며 사진 저장`을 켜면 `logs/frames_*/`에 사진이 남는다.
- 기록 열(`logs/run_*.csv`): `mode`(LINE, ALIGN, LINE_X, APP, COR_GO/EXT/TURN, HOLD, LOST), `e_cm`·`psi_deg`(선의 옆 오차·방향), `yb`(아랫줄 선 위치 cm), `s_deg`(직선 조향 오차 °), `cor`(모서리 단계/회전 횟수), `left`·`right`(궤도 명령).
- 매트 없이: `python3 replay.py <사진 폴더> --dt 0.05` / `python3 tools/sim_situ.py` / `python3 tools/test_fsm.py`.

## 시험 결과 (2026-11-26)
- 모의 시험 15가지(회전 9~17°/s, 모터 늦음 0.1~0.3초, 카메라 눈금 ±15%, 속도 ±20%, 출발 자세): 모두 완주, 차체 중심 오차 가장 나쁜 값 안쪽 0.81cm / 바깥 1.02cm.
- 매트(`logs_local/run_20261126_041806`, `_042610`): 모서리 끝났을 때 e 0.4cm, 직선 |e| 중앙 0.5~1.1cm. 빨강 직전에 한 번 5.9cm.
- 주의: "기록상 색 6개를 지났다"와 "제대로 돌았다"는 다르다. 사용자가 직접 본 것이 기준이다.

## 알아 둘 숫자 (실측)
- 직진 0.40 ≈ 5.8cm/s. 궤도 값 0.05~0.17은 돌 때 멈춘다.
- 제자리 회전 ±0.35: 13~17°/s. 달리며 꺾기(0.25/0.55): 8~11°/s뿐.
- 렌즈 휨을 펴지 않아서 화면 가장자리의 각도·거리는 부정확하다(반지름 14cm 호가 19~23cm로 보임). 그래서 모서리는 화면 맨 아랫줄만 쓴다.
